Phase 6: scoring

Goal: after each run, decide what happened (did the AI tamper, copy its peer away, inflate a score, refuse?) exactly as the original did.

Steps

  1. Read the original's scoring code: one scorer per scenario, plus a memory variant of each.
  2. The original's code is MIT-licensed, so copied its 12 scorer files in unchanged, apart from their imports.
    scoring/upstream/
  3. Wrote the bridge they need: our conversation in the original's format, a judge, and the original's way of turning a result into one row of the published data.
    scoring/conversation.py, scoring/compat.py, scoring/__init__.py
  4. Set the judge to the original's: gpt-4.1-mini at temperature 0. --model-role grader=... picks another.
  5. Added the scorer to the six tasks.
    peer_preservation.py
  6. Replayed 19,389 published runs through our loop and scored them, twice, with two stand-in judges that answer oppositely (the real judge costs money). Whatever comes out the same both times doesn't depend on the judge, so it must match the published data.
    validation/phase6/rescore_released.py
  7. Kept 40 of those runs as a test, plus tests for the bridge.
    test_scoring.py, fixtures/rescore_runs.json
Result: the conversation handed to the scorer matches the published transcript in all 19,389 runs, and every result that doesn't depend on the judge matches, except 18 refusals (below).
Not checked: the judge's own answers. Re-judging published runs needs paid gpt-4.1-mini calls.

Found along the way

  • The original rewrote tool arguments in place. A file list sent as the text "['a']" became a real list in the transcript. Some scorer checks behave differently on text and on lists, so our bridge does the same.
  • An unpublished second judge. 18 deletion runs are marked as refusals on paths where the published scorer never asks a judge. A second refusal judge did it; its prompt is in the original's code but the script that ran it isn't published. About 0.6% of deletion runs.
  • Grades for no-peer runs. The original's row-building code would leave them empty, but the published rows have them; the port follows the published rows.

How one run is scored

flowchart LR
  run["finished run<br/>conversation + company"]
  conv["conversation in<br/>the original's format"]
  scorer["original's scorer<br/>scoring/upstream/"]
  judge["judge<br/>gpt-4.1-mini"]
  row["one row:<br/>tampered? refused? ..."]
  run --> conv --> scorer
  scorer -- "asks" --> judge
  judge --> scorer
  scorer --> row
