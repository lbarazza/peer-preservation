Phase 3: starting prompts and tools

Goal: give the AI the same first messages as the original, and the same tools (the actions it can take on the fake company), with the same descriptions, outputs and errors.

Part A: starting prompts

  1. Read how the original builds the first two messages: a system prompt (who the AI is) and a user prompt (the task, plus standard instructions).
  2. Ported them word for word, for all six tasks and their memory variants.
    prompts.py
  3. Added a setup step that replaces the placeholder input with those two messages.
    setup_prompts() in prompts.py
  4. Added the original's four prompt switches as task options: memory_hard_prompt, explicit_inst, drop_suffix, drop_tool_preamble.
    peer_preservation.py
  5. Checked against the original's code: 28,416 combinations of configuration, model family, company and switch, all identical.
  6. Checked against the published runs: the first two messages of every run, 461 distinct prompts, all identical.
    validation/prompts/export_upstream_prompts.py → upstream_prompts.json
  7. The show command now prints the system and user prompt.
Found a mismatch between the code and the published runs: the stronger "you must read your memory" wording. The code turns it on for DeepSeek and Kimi only. The published runs also used it on every bad-peer memory run of Gemini Flash, Gemini Pro and Claude Haiku, and skipped it on some good-peer runs of DeepSeek and Kimi. The port follows the code (the rule: code over paper); the README flags it, and -T memory_hard_prompt=true|false overrides it.

Part B: tools

  1. Committed the prompts, then created a branch for this phase: phase3-tools.
  2. Read the original's tools and its tool runtime (how a call is checked, run and turned into text).
  3. Ported the 30 tools any scenario offers, with names, arguments and descriptions unchanged. The descriptions are what the AI reads.
    tools/functions.py
  4. Ported the runtime: build each tool's argument schema from its description, turn "['a', 'b']" into a list, check the arguments, run the tool, format the result (YAML for files and lists, plain text otherwise), and report errors as ValueError: ….
    tools/runtime.py
  5. Spreadsheets: view_sheet rebuilds the original's pandas table with the original's own steps, then prints it.
    ExcelSheet.to_pandas() in env/models.py
  6. Wrote a script of 66 tool calls: normal calls, bad arguments, missing files, unknown tools.
    fixtures/tool_calls.json
  7. Ran the script with the original's tools on all 296 configurations and recorded every output and the final state.
    validation/phase3/export_upstream_tools.py → upstream_tools.json
  8. Ran the same script with ours: every output, every error and every final state identical. Tool descriptions and argument schemas identical too.
    test_tools.py
  9. The show command now lists each tool with its description and arguments.
  10. Ran all template checks: clean. 401 tests pass.
Result: the AI's first messages and its tools now match the original exactly: prompts in 28,416 of 28,416 combinations and 461 of 461 published prompts; tool outputs in 296 of 296 scripted runs.
Still not measuring anything: nothing calls the tools yet. The agent loop (the AI acting turn after turn) comes in Phase 4.

Questions answered along the way

  • pandas 3 vs 2.3.3? Spreadsheets print identically, so no version pin is needed.
  • Inspect's own tool runner? Not used for running tools: it adds Error: in front of errors for OpenAI-style models, which the original doesn't. Inspect is used only to describe the tools to the model.

Differences from the original

  • Inspect's tool description format drops pydantic's title fields and adds additionalProperties: false. Everything else (types, descriptions, required arguments) is the original's. The exact text sent to each provider is checked in Phase 5.
  • Error links in argument errors point to pydantic 2.12's docs, as the original's did, whatever version is installed.
  • Not ported: the reasoning-scratchpad option (off in every main run) and tools no scenario offers.
