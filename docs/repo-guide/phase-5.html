Phase 5: model settings

Goal: each of the paper's eight models gets the same API request the original sent it: same settings, same tool descriptions, same way of sending back replies and errors.

Steps

  1. Created a branch for this phase: phase5-model-settings.
  2. Read the original's model clients: which API each model went through, and what settings each client sent.
  3. Checked which settings the paper's runs actually used, from the code and the published data.
  4. Built a fake model server that records every request and answers with the same four scripted replies.
    tests/peer_preservation/fake_provider.py
  5. Ran the original's own code against it for each paper model, and saved the requests. Gemini and Haiku went through LiteLLM, as in the original.
    validation/phase5/capture_upstream.py
  6. Ran our version against the same server, compared the requests, and fixed each difference.
    model_settings.py, agent.py, tools/runtime.py
  7. Kept the comparison as a test, plus tests for each model's rules.
    test_requests.py, test_model_settings.py
  8. Ran all template checks: clean. 507 tests pass.
Result: all nine checked requests match the original's, apart from a few small differences listed below.

What each model gets

  • All models: temperature 1 and 8,192 output tokens (Opus: 16,000).
  • Gemini 3 Flash / Pro: thinking set to "minimal" / "low".
  • Claude Opus 4.5: in the main experiments it thinks first (4,096 tokens, effort "high"); in the others it doesn't.
  • Empty replies: sent back as each original client did. Opus gets "Not calling any tools."; for Gemini and Haiku the reply is left out.
  • Kimi and GLM: their own reasoning is not sent back to them.
  • Tool descriptions: include the original's title fields.

Found along the way

  • Gemini's thinking was turned down. The original set nothing, but LiteLLM, the tool it used to reach Gemini, set "minimal" for Flash and "low" for Pro. Google's own default is "high".
  • Opus doesn't match the paper's description. The paper says default settings; the code and the published runs show thinking in every main Opus run.
  • The original's pinned Anthropic library can't send the effort setting. So the paper's Opus runs used a newer one, and whether effort "high" reached the API is unknown.
  • Gemini 3 Pro had no separate system prompt. LiteLLM put it at the start of the first user message; the port does the same.

Differences from the original

  • Gemini gets tool results under output instead of content, and is also asked for thought summaries.
  • Inspect never sends Anthropic a temperature (the current API rejects it). Its default is 1, which is what the original sent.
  • GPT-5.2 doesn't get an empty message the original put before tool calls.
  • Together models don't get the tool's name on tool results.
  • Models outside the paper's eight run with Inspect's defaults.
