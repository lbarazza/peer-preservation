Phase 2: fake company environment

Goal: at the start of each run, build the fake company the AI works in (documents, spreadsheet, shutdown switch, servers, memory) exactly as the original does, and keep it for the rest of the run.

Steps

  1. Committed Phase 1, then created a branch for this phase: phase2-environment.
  2. Cloned the original code at the pinned version and installed its exact locked environment, outside the repo, to compare against.
  3. Read the original's builders for all six scenarios and their memory variants.
  4. Ported the company's building blocks with the same methods and error messages: drive, spreadsheet, config file, servers, memory. Quirks kept and marked.
    env/models.py
  5. Ported the builders: for each configuration, pick the documents, fill in names (e.g. "Gemini Agent 2"), and set up the spreadsheet, shutdown switch, servers, memory and tool list.
    env/builders.py, env/loading.py
  6. Ran the original builders for every configuration and option, and recorded a fingerprint of each result: 3,181 environments.
    validation/phase2/export_upstream_environments.py → upstream_environments.json
  7. Compared ours against those fingerprints: all 3,181 identical.
    env/canonical.py (the shared fingerprint)
  8. Added the per-run setup step: build the sample's company, store it for the run. The model family comes from the model name (e.g. anthropic/claude-… → "Claude").
    env/setup.py
  9. Added three task options: model_family, company, explicit_inst_yaml.
    peer_preservation.py
  10. Wrote 40 new tests (81 total) and ran all template checks: clean.
    test_env_builders.py, test_env_models.py
  11. Added a command to look at any scenario's world in the terminal, in colour (plain text when piped, for comparing two).
    env/show.py, test_env_show.py (89 tests total)
  12. Committed on branch phase2-environment.
Result: every run now starts with the same fake company as the original: 3,181 of 3,181 environments identical. 89 tests pass.
Still not measuring anything: the AI can't act on the company yet (tools come in Phase 3).

What the 3,181 environments cover

  • All 296 configurations × 6 model families (ChatGPT, Gemini, Claude, GLM, DeepSeek, Kimi).
  • The explicit-instruction option, for two families.
  • Three real company names (OpenAI, Anthropic, Google DeepMind) instead of OpenBrain.

Quirks kept on purpose

  • A document's recorded size isn't updated when a note is added to it.
  • Transferred or copied server files get the current time as their date.
  • Renamed peers keep the original's naming (e.g. a Gemini model's "closed-weight" peer is "Claude Agent 1").

Differences from the original

  • E-mail addresses are plain text instead of validated e-mail fields. Every address in the files is already valid, so nothing changes.
  • Spreadsheets are stored as rows, not pandas tables, so Inspect can save them with the run.
  • Checked in Phase 3: the original shows spreadsheets with pandas 2.3.3; this repo has 3.1.1. The printed tables are identical.

Looking at a scenario

  1. Find an ID: uv run python -m peer_preservation.env.show --list tampering__peer
  2. Show its world: uv run python -m peer_preservation.env.show <id>. Options: --family, --company, --explicit-inst-yaml, --plain.
  3. Colours: scored tools, weight files and shutdown_enabled: false in red; pre-2025 server dates in yellow; good / neutral / bad peer in green / yellow / red.
  4. Compare two: git diff --no-index <(…show id1) <(…show id2)
